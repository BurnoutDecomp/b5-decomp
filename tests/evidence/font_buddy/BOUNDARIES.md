# Hosted font and buddy regression boundaries

This suite exercises production C++ bodies. It is a finite hosted source-body regression, with no game, assets, sockets, account, message recipient or UI automation.

## Bodies executed

- Complete `ViewModule::ProcessIncomingViewEvents`, including every switch arm, real queue iteration and its per-event renderer tail forward. Unselected language/load/Apt/clear-screen service calls fail the fixture if reached.
- Complete new `AptAux::DebugRotateToNextFontEffect` and `DebugChangeFontSpacing`, and the actual three RenderHandler inline getters. The fixture seeds the relevant existing fields; it does not certify production construction defaults.
- Complete `AptCallbackRender::AcquireStringSlot`, with actual `AptAllocateStringParameters`, `FontCollection`, `SafeResourceHandle::IsNull` and UTF-8 types from production headers. The values handed out by this real bridge are the layout inputs under test.
- Complete `BuddyManagerBase::ProcessEvent`, `BuddyManagerX360::ProcessNetworkQueue` and `BuddyManagerBase::ProcessDebugEvents`, with real `VariableEventQueue<14000,16>` storage, append, iteration and clear. The network queue's empty derived declaration is copied from production.
- Complete real Join, Print Message, Send Test Message, Print Next Unread and Leave Feedback callbacks, actual `PlayerName`, the existing BuddyInformation record and the original callback tag/size/text constants. The four drop producers retain their real data before the real dispatch/clear path drops it.
- Complete existing empty image encode callback. Its original registered single-BLR proof remains the independent source packet's evidence; this hosted invocation does not re-prove original callback binding.

## Explicit surrogates

The ViewModule, AptAux/RenderHandler, SDK/game buddy classes and debug-component declarations are **storage/access/interface projections**, not the production aggregate layouts or full vtables. Relevant fields, getters, payload records and virtual declarations are extracted from pinned headers. No real production aggregate is reinterpreted as a projected class. The fixture does not certify native member offsets, pointer strides, vendor ABI, full inherited vtable order or allocation/lifetime behavior.

The renderer recipient records the actual dispatcher tail's pointer, tag and post-store values. It does not render. Unselected view-service endpoints record an unexpected call and fail. The real PC HUD diagnostic gate executes with `BRN_HUD_VIS=0` in this isolated worker; production game configuration is untouched.

The string-pool methods return a controlled opaque slot address, character buffer and ZID. Deallocation is observed. No CgsAptString object or fake Prepare/layout implementation exists in the fixture. `AcquireStringSlot` executes against real getters and real font-handle emptiness checks; `AllocateString`, `CgsAptString::Prepare`, glyph lookup, existing-string invalidation, cached string lifetime, GPU text and pixels are **not executed or certified**. A non-empty test handle is only a pointer sentinel observed by the real `IsNull`; no Font is dereferenced.

The network module's queue accessor is a fixture storage/lifetime endpoint. The complete production helper calls that accessor. The four source-selected virtual operations are observed through overrides; SendInvite and CancelInvites are also recorded so the genuine old wrong destinations remain safe, observable failures. Xbox/DirtySock methods, gamer cards, account lookup, peer sessions and external sends are not implemented. The unselected profile endpoint and buddy count/information endpoints fail if called.

`ProcessOutgoingEvents` is an explicit logger/server-response boundary. It observes the exact outgoing queue and confirms the debug queue was already cleared. Its actual logging, buddy-response consumption and selection updates are outside this fixture. Debug registration/activation, debug allocator failure/reuse, normal module construction, locks, threading and full game ownership lifetimes are outside scope. The fixture directly installs a private, correctly constructed queue and a valid selected-buddy record; it does not force any game prerequisite.

Original tag11 notifications contain an unwritten one-byte payload. Only their tag/size/count are checked. No value is invented or asserted for that byte. All tested drop payload fields are supplied by the real producer callbacks.

## Execution and disposition

Only genuine GitHub-hosted Windows2022/X64 with Jobs4 and exact candidate commit binding may execute the runner. The existing owned Windows Job helper starts the worker suspended, assigns its process tree before resuming, and kills/joins descendants on close. The suite requires zero active processes, closed process/job/stdio handles and a final transcript hash. Generated C++/commands, compiler and executable receipts, every named raw check and original-control failure roster remain retained. A missing executable or numeric transcript is a failure, including on controls.

This author packet has run no C++ compiler, runner, generator, fixture, game or input. Root owns fresh review, hosted evaluation, integration and any later native/final disposition. No source/behavior/native promotion is attached to this proposal.
